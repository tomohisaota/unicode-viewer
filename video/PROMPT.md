# Unicode Viewer 紹介リール — 制作プロンプト

この動画（`reel.html`）を作り直す・直すときの指示書。Claude にこのファイルを渡して
「PROMPT.md に沿って直して」と頼めば、同じ前提から始められる。決まったことはここに足していく。

## 依頼（元の言葉）

- X に共有する紹介動画。かっこよく、わかりやすく、この道具でできることを紹介する
- 見た目は 1 文字なのに中身は複数のコードポイント、という驚きから入る。題材はサイトのサンプル「クセのある文字列」から
- 作りは `../../loan-tenbin/video`（ローン天秤のリール）と同じ。サイトの画面を描き起こし、大きな文字組みで見せるモーショングラフィックス
- 長さは 15 秒が基本。伝えきれなければ 30 秒でよい
- 16:9（1920×1080）と 9:16（1080×1920）。30fps。音なし
- 色・書体はサイトから写す。背景を黒にしない

## 長さ：30 秒にした理由

見せたいことが 4 つある（書記素に分ける／バイト列を覗く／レガシーエンコーディングで確かめる／異体字を見分ける）。
どれもカードの中の数字（コードポイントやバイト）を読んでもらわないと伝わらず、1 つに 4 秒ほど要る。
15 秒では冒頭の驚きと締めを入れると 1 つ 2 秒を切り、字が読めない。ローン天秤でも 15 秒版は駆け足だった。

## 作り

- `reel.html` 一枚。`render(t)` が t 秒時点の見た目を決め打ちで描く純関数
  - プレビュー（requestAnimationFrame）と書き出し（1 コマずつ seek）で同じ絵になる
  - `?v=1` で 9:16、`?render=1` で操作 UI なし・等倍表示
- `render.mjs` が puppeteer-core で 1 コマずつ撮り、ffmpeg-static で mp4 にする。ポートは 8793
- **数字は作らない。** `reel.html` は `./lib.js` を import する。これは `lib.ts`（アプリ本体 `../src/lib` の
  `analyzeString`・`getLegacyEncoding`・`getIvsVariants`・`hasFontGlyph` などを再輸出するだけ）を、
  `render.mjs` のサーバーが esbuild でその場で束ねて配ったもの。生成物は置かない（src/lib を直せば動画にも効く）
- 漢字と異体字はサイトと同じフォント（`../src/app/cjk-ivs-font.css`、`/fonts/` は `../public/fonts/`）で描く。
  書き出す前に `document.fonts.load` で使う字をすべて読み込む（束の中に読めない小さな woff2 があり、その失敗は無視する）
- 絵文字は macOS の Apple Color Emoji。家族の絵文字は今の Apple の字形（人の形の図案）で出る

```
cd video
npm install
npm run preview            # http://localhost:8793/video/reel.html（?v=1 で縦）
npm run stills             # out/stills-h-*.png を 0.5 秒おきに（--at=1.2,3.4 で時刻指定。stills:v で縦）
npm run render             # out/unicode-viewer-reel-16x9.mp4（30 秒）
npm run render:v           # out/unicode-viewer-reel-9x16.mp4
npm run sheet              # out/sheet-16x9.png（mp4 から 1 秒おきのコマを並べた確認用。sheet:v で縦）
```

直したら、まず `stills` で要所を画像で確かめてから `render` する（一本 数分かかる）。豆腐（字が出ない四角）が無いか特に見る。

## 題材（すべてアプリの処理で数える）

- 冒頭・02：家族の絵文字 `👨‍👩‍👧‍👦`（サンプルの最初）。1 文字・7 CP・11 UTF-16・25 UTF-8
- 01：`👨‍👩‍👧‍👦🇯🇵café`。é は NFD（e + U+0301）で入れる。6 文字・14 CP。打った分だけコマごとに数え直す
- 03：サンプル「高髙」と「～〜」をつないだ `高髙～〜`。サイトの初期設定（WHATWG の対応表）で
  Shift_JIS / CP932 / EUC-JP / ISO-2022-JP を引く。髙 は Shift_JIS に無く CP932 で EE E0、〜（U+301C）はどれも非対応
- 04：サンプル「葛󠄀葛」と「邉 × 30」。邉 は IVS 32 登録（異形 30 / 同字形 2）。異形の 30 を並べる
- 「ほかにも」のエンコーディング数（31）は `LANGUAGE_ENCODINGS` の重なりを除いた数
- 本文（「見た目は 6 文字、中身は 14 コードポイント。」など）は計算結果から文を組み立てる（書き写さない）
- 冒頭で漂う記号（U+200D、F0 9F 91 A8、EE E0 …）も、上の処理で出した値

## 見た目

- 色はサイトの `src/app/globals.css` の `:root`（明るいほう）から写す
  - 地 `#fafafa`（gray-50）、面 `#ffffff`、墨 `#171717` / `#4d4d4d` / `#808080`、罫 `#ebebeb`、入力欄 `#f5f5f5`
  - 青 `#0072f5`（地 `#ebf5ff`、字 `#0068d6`）。非対応は赤 `#dc2626`（地 `#fef2f2`）
- 背景は黒にしない。冒頭も白い地（中心が明るい灰の放射グラデーション）。割れ目の光は青
- 書体：英字と画面は Geist、数字・コード・HUD は Geist Mono（サイトと同じ）、日本語は Noto Sans JP（見出しは 700）、
  漢字のセルはサイトの CjkIvsMincho
- 四隅に HUD。左上「unicode-viewer · U+0000 – U+10FFFF」、右上に赤い点と経過時間、
  左下「grapheme · code point · byte」、右下「utf-8 · utf-16 · shift_jis」
- 締めのマークは黒い角丸に白い U と青い +（サイトのアイコンの図案。`public/icon-512.png` は画像が崩れているので描き起こした）

## 構成（30 秒・30fps）

| 秒 | 場面 | 中身 |
|---|---|---|
| 0.0–4.8 | 驚き | 白い地の中央に大きな家族の絵文字。「見た目は、1文字。」。2.0 秒でほどけて 7 つに並ぶ（👨 ZWJ 👩 ZWJ 👧 ZWJ 👦、下に U+ 番号。ZWJ は青い点線の箱で光る）。「中身は、7つ。」とチップ「1 文字 · 7 CP · 11 UTF-16 · 25 UTF-8」が数え上がる。まわりをコードポイントやバイトが奥から漂う |
| 4.8–7.8 | 転換 | 青く光る横線が伸び、地が上下に割れる。「その**1文字**、ほどいてみる。」が 1 字ずつ、下に「コードポイント、バイト列、Shift_JIS まで。」 |
| 7.8–12.0 | 01 分ける。 | 右にサイト風のカード。入力欄に 1 書記素ずつ打ち込まれ、チップが数え直され、セルが並ぶ。中身が複数のセル（家族・国旗・é）が青く縁取られ、凡例が出て、カーソルが家族のセルを押す |
| 12.0–17.0 | 02 覗く。 | カードが家族の絵文字の詳細に変わる。7 つのコードポイントの UTF-8 / UTF-16 が行ごとに出る。👨 の行とサロゲートペアを照らす |
| 17.0–21.5 | 03 確かめる。 | `高髙～〜` を 4 つのエンコーディングで。バイト列か赤い「非対応」で埋まり、髙 の列を照らす。下に「JIS ↔ Unicode マッピング：WHATWG (Microsoft)」 |
| 21.5–25.5 | 04 見分ける。 | 葛（U+845B）と 葛󠄀（U+845B U+E0100）を並べ、IVS の注記。続いて 邉 の異形 30 が波のように並ぶ |
| 25.5–27.5 | ほかにも | 「ほかにも、**ほどける**。」と 6 枚：正規化を比べる／31 のエンコーディング／漢字の出典（IRG）／JIS 水準／見えない文字／URL で共有 |
| 27.5–30.0 | 締め | U+ のマーク、「Unicode Viewer」、`see what's inside every character.`、「その1文字、ほどいてみる。」、黒いボタン「文字列を貼って、ほどく →」、`unicode-viewer.appbatake.com · 無料 · 登録なし`。下に「Unicode Viewer」のコードポイントの帯が流れる |

- 下に 4 つの点の進み具合（01 分ける / 02 覗く / 03 確かめる / 04 見分ける）。段が進むと青で埋まる
- 9:16 版は、段の見出しを上、カードを下に積む。冒頭の記号はほどけた列と字幕の帯を避けて上下に置く

## してはいけないこと

- コードポイント・バイト列・エンコードの可否・異体字の数を書き写す、作る（必ず src/lib の処理で出す）
- アプリ本体のコードを変える（video/ の中だけで完結させる）
- 対応表の違い（WHATWG / Unicode.org）を言わずに「〜 は Shift_JIS で化ける」と言い切る（Unicode.org の対応表なら通る）
